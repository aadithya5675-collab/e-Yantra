## 1. Architecture & Security Overview

```
React 19 (Vite) ── Supabase Auth (login, email verify, JWT)
     │
     │  Bearer <supabase access token>
     ▼
Laravel /api/v1 ──── verifies JWT via JWKS ──► Policies + Form Requests + Actions
     │                                              │
     │  service-role key (backend only)             ▼
     ▼                                     PostgreSQL / SQLite in-memory (Tests)
Supabase Storage (private signed URLs)     Laravel migrations = schema source of truth
```

- **Supabase**: Handles auth identity & email verification.
- **Laravel 13**: Canonical business API with transactional Actions, Form Requests, and Policies.
- **Role Scoping**: Only `admin`/`mentor`/`member` are global roles. Team leadership lives strictly in `team_memberships`.
- **Double-booking & Double-join Prevention**: Database level `lockForUpdate()` transactions prevent race condition double-joins and equipment double-bookings.

## 4. Remaining Manual Steps for Production Deployment

1. **Supabase Private Storage Bucket**:
   Create a private bucket named `arc-evidence` in your Supabase dashboard (no public read policy; download access via short-lived signed URLs generated by Laravel).
2. **Supabase Anon Key Rotation**:
   Rotate the Supabase anon key in your project dashboard if desired, and update `VITE_SUPABASE_ANON_KEY` in `.env`.
3. **Database Migrations on Production Database**:
   Run `php artisan migrate` against your production PostgreSQL instance.
